# Domain docs

Use a single-context layout across this Rust workspace.

## Before exploring

Read the root `CONTEXT.md` and relevant decisions under `docs/adr/`
when they exist.

Proceed silently when these documents are absent. Create them through
domain modeling when terminology or architectural decisions are
actually resolved, rather than generating empty placeholders.

## Vocabulary

Use the terms defined in `CONTEXT.md` consistently in issues, proposals,
code and tests. Identify genuine terminology gaps for domain modeling.

## Decisions

If a proposal conflicts with an existing ADR, identify the ADR and
explain why it should be reconsidered. Surface the conflict before
implementing a contradictory change.
